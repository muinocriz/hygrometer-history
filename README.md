# 温湿度计历史数据

把温湿度计导出的每小时记录做成可视化网页，部署在 GitHub Pages。

在线访问：https://muinocriz.github.io/hygrometer-history/

## 想法与参考来源

图表的思路参考了 WeatherSpark 的气候页面，把同样的展示方式用到自己温湿度计的实测数据上：

- [WeatherSpark · 上海虹桥国际机场全年平均天气](https://weatherspark.com/y/149263/Average-Weather-at-Shanghai-Hongqiao-International-Airport-China-Year-Round)

页面包含：

- 温度、湿度折线图：按日 / 月 / 年切换，显示最高、最低、平均值
- 月内日变化叠加：当月每天的 24 小时曲线叠在一起，阴影为范围、折线为平均，可勾选显示项
- 每小时平均温度瓦片图：按体感区间着色，叠加日出日落与民用晨昏蒙影阴影
- 湿度舒适等级：用 Magnus 公式由温湿度计算露点，按露点分级统计每天的时间占比

缺失数据用虚线连接；一天有效小时数不足时标记为“数据不足”且不计入统计。

## 导出历史数据：`tools/mijia_history.py`

通过蓝牙直连米家蓝牙温湿度计2（LYWSD03MMC，**原厂固件**），读取设备内部存储的每小时最高/最低温湿度，导出为本项目使用的 CSV。不需要刷机，也不需要网关。

### 使用方法

需要 Python 3.10+ 和一台带蓝牙的电脑（macOS / Windows / Linux / 树莓派均可）。

```bash
pip install bleak

# 1. 扫描设备，记下地址
python tools/mijia_history.py scan

# 2. 导出全部历史
python tools/mijia_history.py <地址> -o data/history.csv

# 只导出最近 48 小时（快很多）
python tools/mijia_history.py <地址> -o recent.csv --last 48

# 不填地址，自动连接第一个找到的 LYWSD03MMC
python tools/mijia_history.py auto -o data/history.csv
```

`<地址>`：macOS 上填 `scan` 显示的 UUID（形如 `XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX`）；Windows / Linux 上填 MAC 地址（形如 `A4:C1:38:XX:XX:XX`）。

可选参数：`--idle` 多少秒收不到新数据算卡住（默认 40），`--retries` 最多续传次数（默认 10）。扫描、连接等其余时间参数集中在脚本开头，可直接修改。

### 实现原理

温湿度计的数据有两种取法：

| 方式 | 说明 | 能否取历史 |
|---|---|---|
| 被动监听广播 | 设备每隔几秒广播一次读数（小米 MiBeacon，UUID `0xFE95`），不用连接；但 LYWSD03MMC 原厂固件的广播是加密的，需要 bindkey | 否，只有实时值 |
| GATT 连接 | 主动连接设备，读写特性值、订阅通知 | **是** |

本脚本走 GATT 连接。LYWSD03MMC 原厂固件暴露了以下特性（完整 UUID 均为 `ebe0ccXX-7a0a-4b0c-8a1a-6ff2997da3a6`）：

| 特性 | 用途 | 格式 |
|---|---|---|
| `ebe0ccb7` | 设备时钟（未校时则为开机以来的秒数） | `<I` |
| `ebe0ccb9` | 记录数：总共记录过多少条、当前存了多少条 | `<II` |
| `ebe0ccba` | 读取起点：写入序号，设备从这一条开始推送 | `<I` |
| `ebe0ccbc` | 历史记录：订阅后设备逐条推送 | `<IIhBhB` |

每条历史记录 14 字节，小端：`序号(u32), 时间戳(u32), 最高温度×10(i16), 最高湿度(u8), 最低温度×10(i16), 最低湿度(u8)`。

导出流程：

1. **查找设备**：先扫描到设备再连接。macOS 的 CoreBluetooth 不暴露真实 MAC，且必须在同一进程内扫到设备才能连接，所以不能直接拿地址去连。
2. **时间换算**：设备没有可靠的真实时钟，记录里的时间戳与设备时钟同基准。读出设备时钟，与电脑当前时间求差得到偏移，`真实时间 = 记录时间戳 + 偏移`。记录时间是该小时的**结束**时刻。
3. **接收**：读记录数确定预期条数；如果用了 `--last N`，向 `ebe0ccba` 写入起始序号；然后订阅 `ebe0ccbc`，按序号存进字典（天然去重）。
4. **断点续传**：传输中途停住（超过 `--idle` 秒无新数据）、连接断开或连接出错时，重新查找并连接，把读取起点设为"已收到的最大序号 − 1"接着拉。多读的一条会被去重，保证不漏。收齐预期条数即完成；若只差最后 1 条（当前小时尚未写完）也视为完成；连续 3 次续传都没有新数据则停止。
5. **保存**：结束、出错或按 Ctrl+C 中断时，都会把已收到的记录写入 CSV（UTF-8 带 BOM，Excel 可直接打开）。

协议细节参考了 [uduncanu/lywsd03mmc](https://github.com/uduncanu/lywsd03mmc) 与 [h4/lywsd02](https://github.com/h4/lywsd02)；蓝牙库使用 [bleak](https://github.com/hbldh/bleak)，因此可以跨平台运行。

### 常见问题

**`scan` 找不到设备**
- 关闭手机上的米家 App（或直接关手机蓝牙）。设备同一时间只允许一个连接，被手机连着时会停止广播。
- 让电脑靠近传感器。
- macOS 首次运行时，要在"系统设置 → 隐私与安全性 → 蓝牙"里允许终端（或你用的 IDE）使用蓝牙。

**导出时提示找不到地址 / 扫描不到设备**
- macOS 上要填 `scan` 显示的 UUID，不能填 MAC 地址；这个 UUID 只在本机有效，换电脑要重新扫描。
- 原因同上：检查米家 App 是否已关闭、距离是否太远。也可以改用 `auto`。

**突然连不上（之前能连）**
- 多半是上次中断后，设备或电脑还挂着旧连接。关闭再打开电脑蓝牙，或等 1～2 分钟让旧连接超时后再试。
- **不要拔电池**：原厂固件的历史数据存在设备里，拔电池后大概率丢失。

**接收到一半卡住**
- 这款设备传历史本来就慢（全量可能要几分钟到十分钟），中途停顿或断线比较常见。脚本会自动续传，留意终端里的"已 N 秒没有新数据"提示即可。
- 频繁卡住时，把电脑放到离传感器半米以内；或调小 `--idle`（如 `--idle 20`）让它更早重连。
- 随时可以 Ctrl+C，已收到的数据不会丢。

**导出的时间不对**
- 时间是按"设备时钟 vs 电脑时钟"推算的，运行脚本的电脑本身时间要准确。
- 每行时间表示该小时的结束时刻，例如 `14:00` 代表 13:00–14:00 这一小时。

**没有收到任何历史记录**
- 确认设备是二代方屏 LYWSD03MMC，且是原厂固件。一代圆屏（LYWSDCGQ/01ZM）不存历史；刷了 pvvx 等自制固件的设备，历史要用自制固件自带的工具读取。

### 米家温湿度计3 Mini（MJWSD06MMC）的限制

- **本脚本不支持 3 Mini。** 官方宣传 3 Mini 在设备本地存 3 个月、云端存 6 个月数据，米家 App 里可以看全年曲线；但它**没有沿用**上面这套 `ebe0ccXX` 历史接口：读取数据前必须先用米家的令牌（token）完成身份验证，直接连接无法读取，目前也没有找到读取其原厂固件历史的开源实现。
- **原厂固件拿不到更细的粒度。** 屏幕每 6 秒刷新一次，但这只是显示；官方没有公布存储的记录间隔，能看到的就是米家 App 里的曲线。
- **想要更细粒度的数据，有两条路：**
  1. **刷 [pvvx](https://github.com/pvvx/ATC_MiThermometer) 自制固件**（5.1 版起支持 MJWSD06MMC）。刷完后设备会把每段时间的平均温湿度写进内部存储（循环缓冲，最多 20000 条），记录间隔可设：默认 10 分钟约存 4.5 个月，1 分钟约存两周；用 [GraphMemo.html](https://pvvx.github.io/ATC_MiThermometer/GraphMemo.html) 读取。刷机通过网页蓝牙即可完成，**不需要接线**；只有刷坏需要救砖时，才要拆壳按 pvvx 的 [MJWSD06MMC 页面](https://pvvx.github.io/MJWSD06MMC) 上的触点定义，用 USB 转串口线连接主板重新写入。
  2. **不刷机，长期监听广播自行记录**：用常开设备（如树莓派）持续接收广播并存库，间隔任意。原厂广播是加密的，需要先从米家账号中提取该设备的 bindkey 再解密（例如 Home Assistant 的 Xiaomi BLE 集成）。前提是监听设备一直在线。

## 导入本地数据

页面顶部的导入区域支持点击选择或拖拽，一次可导入多个文件，数据只在浏览器本地处理，不会上传。

- 同一小时（按日期 + 小时，忽略分秒）出现多条记录时合并：最高温度、最高湿度取最大值，最低温度、最低湿度取最小值
- 导入的数据默认与站点自带数据合并显示，可取消勾选“同时包含站点自带数据”只看导入的文件
- 有表头时按列名（最低温度 / 最低湿度 / 最高温度 / 最高湿度）识别列；支持逗号或 Tab 分隔、`2026-11-01` / `2026/11/1` 日期格式、UTF-8 或 GBK 编码
- 刷新页面后导入的数据即清除

## 日出日落位置

页面顶部可按“省 → 地级行政区”选择计算日出日落的位置，默认上海市。目前仅支持列表中的中国大陆地级行政区（含省直辖县级行政单位，不含港澳台），共 369 个，后续会逐步更新。

- 坐标取各行政区的几何中心（三沙市因辖区分散，改用政府驻地永兴岛坐标），与政府驻地的日出时间相差一般在 6 分钟以内
- 时间统一按北京时间（东八区）计算
- 选择后网址会带上 `?city=区划码`，分享链接即可打开同一位置；也可以手写 `?city=乌鲁木齐市`
- 城市坐标数据：[cn-atlas](https://github.com/BarbarossaWang/cn-atlas)（基于 [shengshixian.com](https://github.com/ruiduobao/shengshixian.com) 2023 版行政区划），生成于 `data/cities.js`

## 本地预览

```bash
python -m http.server
# 浏览器打开 http://localhost:8000
```

## 配置

`index.html` 顶部的 `CONFIG`：

- `locationName` / `lat` / `lon` / `tz`：默认的日出日落位置（上海市），页面上可切换
- `minHoursPerDay`：一天有效小时数低于此值视为“数据不足”（默认 12）
